# ambilight_for_pi

Динамическая подсветка телевизора на ленте WS2812B. Цвета по краям экрана считаются по картинке и выводятся
на ленту по SPI. Рассчитано на Orange Pi / Raspberry Pi.

Картинка берётся из одного из двух источников:

| Источник | Откуда | Частота |
|---|---|---|
| **HDMI** | USB-карта захвата (OpenCV) - внешнее устройство, подключённое через HDMI-сплиттер | ~30 кадр/с |
| **ТВ** | сам телевизор: программа `vcap` на ТВ читает видеослой и интерфейс, плата забирает цвета по ADB (папка [`tv/`](tv/README.md)) | ~30 кадр/с |

## Как выбирается источник

- Пока на HDMI **есть картинка**, лента показывает только её. Возврат на HDMI мгновенный.
- Если HDMI **чёрный дольше `HDMI_HOLD_SECONDS`** (по умолчанию 8 с), считается, что сигнала нет, и берётся картинка с ТВ.
  Без сигнала карта захвата отдаёт абсолютно чёрный кадр, и от очень тёмной сцены он не отличается, поэтому выдержка нужна.
  Пока она идёт, лента плавно гаснет, как при тёмной сцене.
- Сигналы **никогда не смешиваются**: в каждый момент времени используется ровно один источник.
- Если нет ни HDMI, ни ТВ (например, ТВ выключен), лента плавно гаснет.
- Телевизор ищется в сети по **MAC-адресу**, а не по IP, поэтому смена адреса после перезагрузки ничего не ломает.
- Подсветка рассчитана на работу без доступа к плате: сервис сам перезапускается (systemd), сам переподключается к ТВ,
  а при зависании основного цикла завершается по watchdog и поднимается заново. Если быстрый `vcap` на ТВ не запускается,
  переключается на запасной режим (~1 кадр/с) и периодически пробует `vcap` снова.

## Требования

- Плата с SPI, к которому подключена лента (`SPI_BUS`, `SPI_CHANNEL` в настройках), и USB-карта захвата.
- Python 3.11+ и пакеты из `reqirements.txt` (`pip install -r reqirements.txt`).
- Для источника ТВ: пакет `adb` на плате (`apt install adb`) и включённая на ТВ отладка по сети (см. [tv/README.md](tv/README.md)).

## Настройка

Все параметры задаются в `.env` (имена и значения по умолчанию - в `settings.py`). Пример - `.env.example`.
Главное:

| Параметр | Что делает |
|---|---|
| `LEDS_LEFT`, `LEDS_TOP`, `LEDS_RIGHT`, `LEDS_BOTTOM` | число светодиодов по сторонам |
| `HDMI_ENABLED` | включить/выключить источник HDMI (карта захвата). Выключенный не открывается, `/capture/*` отвечает 409 |
| `TV_ENABLED` | включить/выключить источник ТВ |
| `TV_MAC` | MAC Wi-Fi телевизора; пусто - источник ТВ тоже выключен |
| `HDMI_HOLD_SECONDS` | сколько секунд чёрного HDMI терпим до перехода на ТВ |
| `HDMI_PICTURE_THRESHOLD` | максимум по каналам (0..255), выше которого кадр HDMI считается картинкой. Должен быть заметно выше `hdmi_peak` из `/status` при отключённом HDMI (пустой кадр зависит от `CAPTURE_BRIGHTNESS`: при 40 это ~0) |
| `TV_FLAT_GRAY_AS_BLANK`, `TV_FLAT_TOLERANCE`, `TV_FLAT_MIN`, `TV_FLAT_MAX`, `TV_FLAT_FRAMES` | защищённый (HDCP) вход, например Steam Deck через док, ТВ отдаёт в захват как ровный серый кадр. Если кадр однородный, нейтрально-серый и по яркости между `TV_FLAT_MIN` и `TV_FLAT_MAX` в течение `TV_FLAT_FRAMES` кадров подряд, он считается «нет изображения»: в ленту ничего не отдаётся, и она плавно гаснет. Настоящий чёрный и белый экраны этим не затрагиваются |
| `LED_BRIGHTNESS`, `LED_SATURATION`, `LED_WHITE_REDUCTION`, `LED_WHITE_POWER` | цветокоррекция ленты для любого источника: общая яркость (1.0 - как есть, выше - ярче, до 3.0), усиление насыщенности, приглушение белого и бледных цветов. Подбирать удобно на лету: `curl -X POST localhost:8000/led/grade -H 'Content-Type: application/json' -d '{"brightness":0.5,"saturation":1.8}'` (действует до перезапуска, постоянные значения - в `.env`); `GET /led/grade` показывает текущие |
| `TV_TRANSPORT` | как кадры идут с ТВ: `udp` (по умолчанию) - программа на ТВ шлёт их на Pi напрямую датаграммами (ADB только запускает её); `adb` - всё через ADB. Если UDP не проходит (нет кадров 10 с), на 2 минуты автоматически включается ADB. В записи реального потока при одинаковой задержке воспроизведения UDP даёт в разы меньше «недобора» кадров, чем ADB (при 80 мс: 0.3% против 5-15%). `tv_transport` в `/status` показывает, что используется сейчас |
| `TV_CAPTURE_FPS` | частота съёмки на ТВ (60). Нагрузка на ТВ растёт пропорционально: ~26% одного ядра при 30, ~39% при 45, ~50% при 60 кадр/с. 60 кадр/с позволяют меньшую задержку воспроизведения при той же плавности |
| `TV_PLAYOUT_DELAY`, `TV_PLAYOUT_DELAY_ADB` | задержка воспроизведения кадров с ТВ, секунды: 0.07 для UDP и 0.15 для запасного потока через ADB. Сеть доставляет кадры пачками, поэтому они ставятся на временную шкалу по времени съёмки (метка в каждом кадре от `vcap`) и воспроизводятся с постоянной задержкой и линейной интерполяцией. Больше - плавнее при плохом Wi-Fi, но подсветка запаздывает. Показатель `tv_starved` в `/status` - доля тактов, когда нужный кадр не успел прийти: если он постоянно выше 0.1, задержку стоит увеличить |
| `MAIN_LOOP_HZ`, `LED_REFRESH_HZ` | частота главного цикла (60); лента перерисовывается при каждом его такте, а `LED_REFRESH_HZ` - наименьшая частота, когда новых данных нет. Реальная частота ленты - `led_hz` в `/status` |
| `LEDS_THICKNESS` | сколько светодиодов занимает один сегмент картинки: 1 - у каждого светодиода свой цвет (самая плавная картинка), 2 и больше - группами |
| `TV_CAPTURE_*` | размер, частота и режим (видео+интерфейс или только видео) кадра с ТВ |
| `SMOOTHING_TAU_*` | постоянные времени сглаживания (сек): HDMI, ТВ, запасной режим ТВ, режим «источников нет» |

Внешний вход ТВ (HDMI) захватывается только пока источник не шифрует сигнал: если на входе включён HDCP, ТВ подставляет вместо картинки ровный серый
кадр (`/status` показывает `tv_blank: true`), и лента гаснет. Устройства без HDCP (например, ноутбук) захватываются нормально.

Источник ТВ на стороне телевизора не поддерживает нижнюю сторону ленты (`LEDS_BOTTOM` должен быть 0).

Источники включаются независимо: можно оставить только HDMI (`TV_ENABLED=false`), только ТВ (`HDMI_ENABLED=false`,
приоритет и выдержка тогда не нужны) или оба. Если выключены оба, лента остаётся тёмной (в журнале будет предупреждение).
Статус в `/status` показывает `hdmi_enabled` и `tv_enabled`.

## Запуск

```bash
cp .env.example .env     # поправить под себя
python3 run.py
```

Как служба (рекомендуется, плата должна сама подниматься и перезапускаться):

```bash
# поправить WorkingDirectory в deploy/ambilight.service
cp deploy/ambilight.service /etc/systemd/system/ambilight.service
systemctl daemon-reload
systemctl enable --now ambilight
journalctl -u ambilight -f       # лог: смена источника, состояние ТВ-источника
```

## Питание платы от USB ТВ и выключение ТВ

Если плата (и, например, колонка) питается от USB-порта ТВ и этот же порт соединён с ТВ по данным, ТВ считает подключённого USB-хоста
активным (источник пробуждения ядра `gadget-connect`), не уходит в глубокий сон и не снимает питание с порта: при выключении с пульта гаснет только экран.
Чтобы выключение ТВ снова обесточивало плату, плата отключает данные этого USB-подключения (питание остаётся). Подсветка по Wi-Fi/ADB не страдает, но `adb` по USB
перестаёт быть доступен.

```bash
cp deploy/99-tv-usb-nodata.rules /etc/udev/rules.d/
cp deploy/tv-usb-nodata.service /etc/systemd/system/
udevadm control --reload && systemctl daemon-reload && systemctl enable --now tv-usb-nodata
```

Правило подходит к устройству `18d1` с названием `am30am` (так ТВ виден на USB); для другого ТВ поправьте `idVendor`/`product` в обоих файлах (`lsusb`, `/sys/bus/usb/devices/*/product`).
Отменить: `systemctl disable --now tv-usb-nodata && rm /etc/udev/rules.d/99-tv-usb-nodata.rules`.

## HTTP-интерфейс

Порт `INTERFACE_PORT` (по умолчанию 8000).

| Метод | Путь | Что делает |
|---|---|---|
| POST | `/led/enable`, `/led/disable` | включить / выключить ленту |
| GET | `/led/status` | включена ли лента |
| POST | `/capture/set/saturation`, `/capture/set/contrast`, `/capture/set/brightness` | настройки карты захвата, тело `{"value": N}` |
| GET | `/status` | активный источник (`HDMI` / `TV` / `NONE`), пик яркости HDMI, режим и возраст кадра ТВ, адрес ТВ |

## Диагностика

- `curl http://<плата>:8000/status` - какой источник сейчас управляет лентой.
- Лента не горит при выключенном HDMI: проверьте `TV_MAC`, что на ТВ включён ADB, и `journalctl -u ambilight`
  (строки `[tv] TV found at ...`, `[main] source: ...`).
- `tv_mode: legacy` в статусе - работает запасной режим (~1 кадр/с), значит `vcap` на ТВ не запускается (см. [tv/README.md](tv/README.md)).

## Тесты

```bash
python3 -m unittest discover -s tests -v
```

Тесты проверяют логику выбора источника, пересчёт сегментов и разбор таблицы соседей. Железо (SPI, камера, ТВ) не нужно.

## Скорость отклика источника ТВ

Подсветка от карты захвата отзывчивее, чем от ТВ, потому что у карты нет сети. Для ТВ задержку определяют:

1. **Захват на ТВ** (1 кадр = 1/`TV_CAPTURE_FPS` с) плюс работа драйвера.
2. **Wi-Fi.** Wi-Fi-чип этого ТВ (`atbm602x`) работает только на 2,4 ГГц, канал делят с соседями, и задержка сильно «плавает»: в замерах от 6 мс до всплесков 100-300 мс (редко до 1 с). Улучшают: другой, менее занятый канал на роутере; проводное подключение Pi (порт Ethernet на плате есть, `end0`), тогда одно из двух беспроводных звеньев исчезает.
3. **Транспорт** (`TV_TRANSPORT`): UDP вместо ADB.
4. **Запас воспроизведения** (`TV_PLAYOUT_DELAY`): сглаживает пачки кадров ценой задержки. Подбирается по `tv_starved` в `/status` (доля тактов, когда кадр не успел): держите её ниже ~0.05.

Если подсветка кажется запаздывающей, уменьшайте `TV_PLAYOUT_DELAY` (например, до 0.05) и смотрите на `tv_starved`; если подёргивает, увеличивайте.

Карта захвата остаётся запасным вариантом: `HDMI_ENABLED=true` в `.env` включает её (с приоритетом над ТВ, пока на ней есть картинка).
