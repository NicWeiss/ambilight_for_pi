# tv - программы на стороне телевизора

Эти файлы нужны, чтобы подсветка работала и от картинки **самого телевизора** (YouTube, Kinopub, меню лаунчера и т.д.),
а не только от внешнего устройства на HDMI. Плата (`tv.py`) сама ставит их на ТВ по ADB и запускает; вручную
ничего делать не нужно, если выполнено «Подготовка ТВ».

Проверено на: Franko (прошивка Cultraview, Amlogic, `am30am`), Android 13, 32-бит ARM.

## Что здесь

| Файл | Назначение |
|---|---|
| `vcap` | **Основная программа.** Читает кадр с V4L2-устройства `/dev/video12` (amlvideo2), считает средние цвета сегментов по краям и отдаёт их в stdout. ~30 кадр/с, ~170-330 байт на кадр. |
| `vcap.c` | Исходник `vcap` (без libc, на «сырых» системных вызовах ARM). |
| `build.sh` | Сборка `vcap` из `vcap.c` (`clang` + `lld`, NDK не нужен). |
| `cap.sh`, `screencatch_p` | **Запасной режим** (~1 кадр/с), на случай если `vcap` не запускается. |
| `make_legacy.sh` | Пересоздаёт `screencatch_p` из штатной программы самого ТВ. |
| `inputbridge/` | Android-приложение: **HDMI-входы и кнопка INPUT** в сторонних лаунчерах (Projectivy и др.). К подсветке отношения не имеет. См. [inputbridge/README.md](inputbridge/README.md). |

`screencatch_p` - это копия штатной программы `/vendor/bin/screencatch` (Amlogic, закрытый код) с одной исправленной
строкой, поэтому её не стоит публиковать вместе с репозиторием; при необходимости пересоздаётся `make_legacy.sh`.

## Подготовка ТВ (один раз)

Нужна отладка ADB по сети, порт 5555.

1. Включить режим разработчика и «Отладку по USB» (в стандартном меню Franko раздела нет). Чистые Android-настройки
   открываются приложением Activity Launcher: экран `com.android.settings/.Settings$MyDeviceInfoActivity` (7 раз нажать
   «Номер сборки»), затем `.Settings$DevelopmentSettingsDashboardActivity` - включить «Отладку по USB».
2. Включить ADB по сети в сервисном меню производителя (Activity Launcher -> `com.cultraview.ctvfactorymenu` ->
   `.ui.FactoryMenuActivity` -> **Other options -> ADB Mode**), затем перезагрузить ТВ. Остальные пункты меню не трогать.
   После перезагрузки порт 5555 должен быть открыт: `nmap -p 5555 <IP ТВ>`.
3. С платы проверить: `adb connect <IP ТВ>:5555 && adb -s <IP ТВ>:5555 shell echo ok`.
   Запроса подтверждения на ТВ не появляется, ключ принимается сам.
4. Узнать MAC Wi-Fi ТВ (`WIFI MAC` вверху сервисного меню, либо `ip neigh` на плате после обращения к ТВ)
   и прописать его в `.env` как `TV_MAC`.

ADB по сети на ТВ должен оставаться включённым, пока нужна подсветка от ТВ.

## Установка вручную (обычно не нужна)

```bash
adb connect <IP>:5555
adb -s <IP>:5555 push vcap /data/local/tmp/vcap
adb -s <IP>:5555 shell chmod 755 /data/local/tmp/vcap
```

Проверка (на экране ТВ должна быть картинка, команда выведет число принятых байт):

```bash
adb -s <IP>:5555 exec-out /data/local/tmp/vcap 320 180 30 1 15 26 15 40 30 | head -c 16800 | wc -c   # 100 кадров
```

## Использование `vcap`

```
vcap [W H FPS TYPE [L T R EX EY]]      по умолчанию: 160 90 20 1
```

- `W H` - размер кадра, который отдаёт драйвер. **Меньше 320x180 нельзя**: драйвер тогда выдаёт картинку с чёрными
  полями (только центральные ~128 пикселей).
- `FPS` - частота кадров, `TYPE` - 0 только видео, 1 видео + интерфейс ТВ.
- Без остальных аргументов в stdout идут целые кадры BGR24 (`W*H*3` байт на кадр).
- С `L T R EX EY` в stdout идут только цвета сегментов: `L` сегментов левой стороны (снизу вверх), `T` верхней
  (слева направо), `R` правой (сверху вниз), по 3 байта BGR на сегмент. `EX`/`EY` - толщина боковой/верхней полосы
  анализа в пикселях кадра.
- В режиме сегментов перед цветами каждого кадра идёт метка времени съёмки: 4 байта, little-endian, миллисекунды по `CLOCK_MONOTONIC` ТВ (переполняется раз в 49 дней). По ней плата воспроизводит кадры с постоянной задержкой, а не «по мере прихода». Версия `vcap` на ТВ сверяется по контрольной сумме и обновляется автоматически.
- Всегда отдаётся самый свежий кадр; когда читатель отключается, программа завершается сама.

Сборка из исходников:

```bash
./build.sh        # нужны clang и lld
```

## Как кадры доходят до платы

По умолчанию (`TV_TRANSPORT=udp`) плата запускает на ТВ через ADB команду `vcap ... | nc -u <адрес платы> <порт>`: кадры идут на плату UDP-датаграммами
напрямую, ADB в потоке данных не участвует (в нём кадры копились и приходили пачками). В датаграмме целое число кадров
по `4 + 3 * (L+T+R)` байт. Если UDP не проходит, плата на 2 минуты переходит на поток через ADB.
Нужна утилита `nc` на ТВ (есть в системе, `/system/bin/nc`). Когда плата останавливает поток, она сама завершает `vcap` и `nc` на ТВ; если плата
отключилась внезапно, они продолжат слать данные в пустоту, пока плата не запустится снова или их не остановят вручную:
`adb -s <IP> shell "pkill vcap; pkill nc"`.

## Запасной режим

Если `vcap` сразу завершается (например, не открывается устройство `/dev/video12`), плата переходит на
`cap.sh` + `screencatch_p` (~1 кадр/с, частота зашита в самой программе ТВ) и через 2 минуты пробует `vcap` снова
(сразу, если запасной режим тоже не даёт кадров). Паузу в кадрах (например, ТВ в режиме ожидания) `vcap` переживает
сам: просто ждёт, поток возобновляется, а при уходе читателя программа завершается и освобождает канал захвата.
`cap.sh` создаёт на ТВ 5000 именованных каналов в `/data/local/tmp/capf`, через них идёт поток кадров.

## Лаунчер по умолчанию (Projectivy и др.)

Назначить лаунчер главным без диалога выбора (после установки или обновления назначение может сброситься):

```bash
adb -s <IP>:5555 shell cmd package set-home-activity com.spocky.projengmenu/.ui.home.MainActivity
adb -s <IP>:5555 shell cmd package resolve-activity --brief -a android.intent.action.MAIN -c android.intent.category.HOME   # проверка
```

- **Не используйте `am force-stop` на пакете лаунчера**: это стирает назначение, и по HOME появляется окно
  «Выберите главное приложение» над чёрным экраном. Для перезапуска нажмите HOME или запустите активность заново.
- Если после этого окно всё же появилось - повторите `set-home-activity`.
- Если экран чёрный, а лаунчер в списке активностей есть, ТВ, скорее всего, стоит на входе HDMI без сигнала (`com.cultraview.livetv`):
  нажмите HOME ещё раз.
- Плитки HDMI/AV и кнопка INPUT в сторонних лаунчерах - см. [inputbridge/README.md](inputbridge/README.md).

## Ограничения

- Защищённый контент (DRM, например Netflix) в видеослой не попадает, лента от него не светит.
- Устройство `/dev/video12` обслуживает одного клиента за раз.
- Нижняя сторона ленты в режиме ТВ не поддерживается.
- Если ТВ в режиме ожидания и не отвечает по сети, лента гаснет, при включении ТВ подсветка возвращается сама.

## Удаление с ТВ

```bash
adb -s <IP>:5555 shell rm -rf /data/local/tmp/vcap /data/local/tmp/cap.sh /data/local/tmp/capf /data/local/tests/vendor/screencatch_p
```
