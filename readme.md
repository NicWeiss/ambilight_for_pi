# ambilight_for_pi

Динамическая подсветка телевизора на ленте WS2812B. Цвета по краям экрана считаются по картинке и выводятся
на ленту по SPI. Рассчитано на Orange Pi / Raspberry Pi.

Картинка берётся из одного из двух источников:

| Источник | Откуда | Частота |
|---|---|---|
| **HDMI** | USB-карта захвата (OpenCV) - внешнее устройство, подключённое через HDMI-сплиттер | ~30 кадр/с |
| **ТВ** | сам телевизор: программа `vcap` на ТВ читает видеослой и интерфейс, плата забирает цвета по ADB (папка [`tv/`](tv/README.md)) | ~30 кадр/с |

## Как выбирается источник

- Пока на HDMI **есть картинка**, лента показывает только её. Возврат на HDMI мгновенный.
- Если HDMI **чёрный дольше `HDMI_HOLD_SECONDS`** (по умолчанию 8 с), считается, что сигнала нет, и берётся картинка с ТВ.
  Без сигнала карта захвата отдаёт абсолютно чёрный кадр, и от очень тёмной сцены он не отличается, поэтому выдержка нужна.
  Пока она идёт, лента плавно гаснет, как при тёмной сцене.
- Сигналы **никогда не смешиваются**: в каждый момент времени используется ровно один источник.
- Если нет ни HDMI, ни ТВ (например, ТВ выключен), лента плавно гаснет.
- Телевизор ищется в сети по **MAC-адресу**, а не по IP, поэтому смена адреса после перезагрузки ничего не ломает.
- Подсветка рассчитана на работу без доступа к плате: сервис сам перезапускается (systemd), сам переподключается к ТВ,
  а при зависании основного цикла завершается по watchdog и поднимается заново. Если быстрый `vcap` на ТВ не запускается,
  переключается на запасной режим (~1 кадр/с) и периодически пробует `vcap` снова.

## Требования

- Плата с SPI, к которому подключена лента (`SPI_BUS`, `SPI_CHANNEL` в настройках), и USB-карта захвата.
- Python 3.11+ и пакеты из `reqirements.txt` (`pip install -r reqirements.txt`).
- Для источника ТВ: пакет `adb` на плате (`apt install adb`) и включённая на ТВ отладка по сети (см. [tv/README.md](tv/README.md)).

## Настройка

Все параметры задаются в `.env` (имена и значения по умолчанию - в `settings.py`). Пример - `.env.example`.
Главное:

| Параметр | Что делает |
|---|---|
| `LEDS_LEFT`, `LEDS_TOP`, `LEDS_RIGHT`, `LEDS_BOTTOM` | число светодиодов по сторонам |
| `HDMI_ENABLED` | включить/выключить источник HDMI (карта захвата). Выключенный не открывается, `/capture/*` отвечает 409 |
| `TV_ENABLED` | включить/выключить источник ТВ |
| `TV_MAC` | MAC Wi-Fi телевизора; пусто - источник ТВ тоже выключен |
| `HDMI_HOLD_SECONDS` | сколько секунд чёрного HDMI терпим до перехода на ТВ |
| `HDMI_PICTURE_THRESHOLD` | максимум по каналам (0..255), выше которого кадр HDMI считается картинкой. Должен быть заметно выше `hdmi_peak` из `/status` при отключённом HDMI (пустой кадр зависит от `CAPTURE_BRIGHTNESS`: при 40 это ~0) |
| `TV_CAPTURE_*` | размер, частота и режим (видео+интерфейс или только видео) кадра с ТВ |
| `SMOOTHING_TAU_*` | постоянные времени сглаживания (сек): HDMI, ТВ, запасной режим ТВ, режим «источников нет» |

Источник ТВ на стороне телевизора не поддерживает нижнюю сторону ленты (`LEDS_BOTTOM` должен быть 0).

Источники включаются независимо: можно оставить только HDMI (`TV_ENABLED=false`), только ТВ (`HDMI_ENABLED=false`,
приоритет и выдержка тогда не нужны) или оба. Если выключены оба, лента остаётся тёмной (в журнале будет предупреждение).
Статус в `/status` показывает `hdmi_enabled` и `tv_enabled`.

## Запуск

```bash
cp .env.example .env     # поправить под себя
python3 run.py
```

Как служба (рекомендуется, плата должна сама подниматься и перезапускаться):

```bash
# поправить WorkingDirectory в deploy/ambilight.service
cp deploy/ambilight.service /etc/systemd/system/ambilight.service
systemctl daemon-reload
systemctl enable --now ambilight
journalctl -u ambilight -f       # лог: смена источника, состояние ТВ-источника
```

## HTTP-интерфейс

Порт `INTERFACE_PORT` (по умолчанию 8000).

| Метод | Путь | Что делает |
|---|---|---|
| POST | `/led/enable`, `/led/disable` | включить / выключить ленту |
| GET | `/led/status` | включена ли лента |
| POST | `/capture/set/saturation`, `/capture/set/contrast`, `/capture/set/brightness` | настройки карты захвата, тело `{"value": N}` |
| GET | `/status` | активный источник (`HDMI` / `TV` / `NONE`), пик яркости HDMI, режим и возраст кадра ТВ, адрес ТВ |

## Диагностика

- `curl http://<плата>:8000/status` - какой источник сейчас управляет лентой.
- Лента не горит при выключенном HDMI: проверьте `TV_MAC`, что на ТВ включён ADB, и `journalctl -u ambilight`
  (строки `[tv] TV found at ...`, `[main] source: ...`).
- `tv_mode: legacy` в статусе - работает запасной режим (~1 кадр/с), значит `vcap` на ТВ не запускается (см. [tv/README.md](tv/README.md)).

## Тесты

```bash
python3 -m unittest discover -s tests -v
```

Тесты проверяют логику выбора источника, пересчёт сегментов и разбор таблицы соседей. Железо (SPI, камера, ТВ) не нужно.
